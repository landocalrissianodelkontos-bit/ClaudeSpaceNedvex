# Судебная статистика по судье арбитражного суда

Триггерная фраза: `анализ судьи`.

Используй этот скилл, когда нужно посчитать практику конкретного судьи арбитражного суда за период: сколько постановлений или дел рассмотрено, сколько судебных актов оставлено без изменения, отменено, изменено, и сколько актов не попадают в эти категории.

## Входные данные

Уточни или извлеки из запроса:

- ФИО судьи, например `Журавлев Ю.А.`
- Суд, например `18 ААС`
- Период, например `01.01.2025-30.06.2026`

## Общий подход

Сначала собери широкую базу актов, затем строго отфильтруй документы, где судья действительно входит в состав суда, и только после этого классифицируй резолютивные части.

Не считай документ только потому, что фамилия судьи встречается в тексте. Фамилия должна быть в блоке состава суда, обычно рядом с фрагментом `суд в составе:`.

## Источники

1. Сначала попробуй KAD/RAS:
   - `https://kad.arbitr.ru`
   - `https://ras.arbitr.ru`

2. Не обходи капчу, 451 и иные технические ограничения. Если KAD/RAS возвращает 451 или требует ручную проверку, зафиксируй ограничение и переходи к fallback.

3. Fallback: используй `sudrf.cntd.ru` / `api.docs.cntd.ru` как доступное зеркало текстов судебных актов.

## Сбор через api.docs.cntd.ru

Найди `department_id` нужного суда на странице суда `sudrf.cntd.ru` или через API. Например, для 18 ААС использовался `department=878400003`.

Запрашивай документы через:

```text
https://api.docs.cntd.ru/v1/search
```

Базовые параметры:

```text
query=<ФИО судьи>
department=<department_id>
type=<id постановлений суда>
date[]=YYYY-MM-DD
date[]=YYYY-MM-DD
date_join=between
```

Проверяй разные варианты написания ФИО:

```text
Иванов И.И.
Иванов И. И.
Иванова И.И.
Иванова И. И.
```

Для каждого найденного документа скачай полный текст блоками:

```text
/document/{id}/content/text/blocks/size
/document/{id}/content/text/block/{block_index}
```

Кэшируй тексты локально, чтобы можно было перезапускать классификацию без повторного скачивания всех актов.

## Фильтрация документов

Оставляй документ в выборке только если одновременно выполнены условия:

- это нужный суд;
- это постановление;
- дата документа внутри периода;
- судья указан именно в блоке состава суда;
- фамилия не является только упоминанием в истории движения дела, например `произведена замена судьи ...`.

Практический фильтр: выдели участок текста от `в составе` до ближайшего маркера `при ведении`, `рассмотрел`, `рассмотрев`, `при участии`. Ищи ФИО судьи именно в этом участке.

## Классификация

Классифицируй резолютивную часть после последнего маркера:

```text
ПОСТАНОВИЛ:
```

Правила:

- `оставить без изменения` -> `оставлено без изменения`
- `отменить` -> `отменено`
- `изменить` -> `изменено`
- взыскание госпошлины, судебных расходов, возврат пошлины, перечисление депозита, переход к рассмотрению по правилам первой инстанции и другие процедурные постановления -> `прочее`

Если в резолютивной части одновременно есть отмена и изменение, учитывай приоритет по смыслу результата. Обычно `изменить` выделяй отдельно, а `отменить` относись к отмене, если суд отменяет акт полностью или в части и принимает новый результат.

## Проверки качества

Перед итогом обязательно проверь:

- количество сырых поисковых попаданий;
- количество документов после строгой проверки состава суда;
- несколько примеров `оставлено без изменения`, `отменено`, `изменено`;
- все документы категории `прочее`;
- количество уникальных дел отдельно от количества постановлений.

Сохраняй:

- CSV с каждым актом и классификацией;
- JSON с каждым актом и классификацией;
- summary JSON с агрегированными цифрами;
- короткий Markdown-отчет.

## Итоговый ответ

Отвечай кратко и цифрово:

```text
Судья: <ФИО>
Суд: <суд>
Период: <период>

Постановлений в составе суда: N
Уникальных дел: N
Оставлено без изменения: N
Отменено: N
Изменено: N
Прочее: N
Отменено + изменено: N
```

Если KAD/RAS были недоступны, прямо укажи, что расчет сделан через `sudrf.cntd.ru` / `api.docs.cntd.ru` как fallback из-за технического ограничения доступа к KAD/RAS.
